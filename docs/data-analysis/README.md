# 데이터 분석 및 위험 규칙

## 맡은 역할

안심계약 레이더에서 **제공 데이터 분석과 설명 가능한 임대차 위험 규칙 설계**를 담당했습니다.

구체적인 담당 범위는 다음과 같습니다.

- HUG 합성데이터와 비식별 상담자료의 구조·품질 확인
- 주택유형과 보증금비율의 특징 분석
- 경매·배당·대위변제 자료의 회수 맥락 분석
- 상담사례에서 반복되는 위험상황과 미확인 정보 정리
- 근저당·압류·공동담보·반환보증 등에 대한 위험 규칙 설계
- 입력정보의 확인 정도를 나타내는 분석 신뢰도 설계
- 주소 기반 시연을 위한 모의 매물과 입지 참고정보 제작
- 백엔드 담당자에게 전달할 JSON 계약과 결과 예시 작성

## 분석에 활용한 도구와 방법

| 도구·방법 | 활용 내용 |
|---|---|
| Python | 단계별 분석 스크립트, 위험 규칙, 모의 결과 생성 코드 작성 |
| Pandas | CSV·Excel 불러오기, 결측치·중복·그룹별 분포 분석 |
| `read_csv`, `read_excel` | 합성데이터와 상담자료를 데이터프레임으로 변환 |
| 인코딩 순차 확인 | `UTF-8-SIG`, `CP949`, `EUC-KR`, `UTF-8` 순서로 한글 CSV 읽기 |
| `isna`, `duplicated` | 비어 있는 값과 완전히 중복된 행 확인 |
| `to_numeric` | 금액·비율·소요일을 숫자로 변환하고 변환 실패값 확인 |
| `groupby`, `value_counts` | 주택유형·채권유형·분쟁유형별 건수와 비율 계산 |
| 중앙값·분위수 | 큰 이상값의 영향을 줄이면서 일반적인 분포와 상위 구간 확인 |
| 키워드 포함 분석 | 상담문장에서 근저당·압류·말소·경매 등의 단어 포함 여부 확인 |
| JSON·Markdown | 분석 결과와 위험 규칙 저장, 사람이 읽을 수 있는 보고서 작성 |
| unittest | 위험 규칙과 모의 결과를 자동으로 검증 |
| Git·GitHub | `feature/data-analysis` 브랜치에서 결과물 관리와 공유 |

위험 판정에는 머신러닝 예측모델을 사용하지 않았습니다. 정상계약 전체를 포함한 학습데이터가 없고 결과의 이유를 명확히 보여줘야 하므로, 분석 결과와 상담맥락을 근거로 사람이 확인할 수 있는 규칙 기반 방식을 선택했습니다.

## 실제로 진행한 작업

### 1단계. 데이터 구조와 품질 확인

제공받은 CSV 7개와 Excel 1개, 총 8개 파일을 모두 읽고 분석 가능한 상태인지 확인했습니다.

Pandas의 `read_csv`와 `read_excel`로 파일을 읽고, `isna`·`duplicated`·`to_numeric`을 이용해 결측치, 중복행, 숫자 변환 실패, 음수값과 0값을 검사했습니다. 상담문장과 상세주소처럼 민감할 수 있는 컬럼은 결과 보고서에 원문 예시를 남기지 않았습니다.

- 파일별 행 수와 컬럼 구조 확인
- 비어 있는 값과 중복 행 확인
- 사고일수·배당일수의 음수값 확인
- 주소처럼 보이는 비식별 위험값 확인
- 원본 데이터는 수정하지 않고 문제점만 별도 보고서로 기록

중복과 이상값은 정확한 업무 기준이 없는 상태에서 임의로 삭제하지 않았습니다.

결과: [`analysis/01_data_quality`](../../analysis/01_data_quality)

### 2단계. 주택유형과 보증금비율 분석

주택가액 대비 임대보증금 데이터 69,435건을 분석했습니다.

주택유형 명칭을 아파트·오피스텔·다가구·다세대·연립·단독으로 표준화한 뒤 `groupby`로 유형별 집단을 만들었습니다. 각 집단에서 평균, 중앙값, 25·75·90분위수와 80%·90%·100% 이상 비중을 계산했습니다.

- 전체 보증금비율 중앙값은 94.6%
- 다세대주택은 90% 이상 비율이 많이 나타남
- 아파트는 다른 주택유형보다 상대적으로 낮게 나타남
- 오피스텔·연립주택도 높은 보증금비율 사례가 확인됨
- 다가구는 건물 전체가액과 개별 보증금을 비교할 수 있어 단순 비율 해석이 위험함

주택유형만으로 위험점수를 주지 않고, 가격 출처와 비교 단위까지 확인하도록 결정했습니다.

결과: [`analysis/02_housing_deposit_ratio`](../../analysis/02_housing_deposit_ratio)

### 3단계. 경매·배당·대위변제 분석

사고가 발생한 이후 보증금이 어떻게 회수되는지 분석했습니다.

경매자료는 주택유형별로 묶어 배당 0원 비율과 배당금·대위변제금액 중앙값을 계산했습니다. 배당자료는 채권유형별 회수율과 처리기간의 중앙값·90분위수를 확인했습니다. 대위변제 자료는 원본과 완전 중복행 제거 결과를 함께 계산해 중복 처리에 따라 합계가 얼마나 달라지는지 민감도 분석을 했습니다.

- 경매자료 32,542건의 배당 여부와 결측값 확인
- 배당자료 28,961건의 처리기간 분포 확인
- 임대보증 대위변제 자료의 중복 여부와 금액 차이 확인
- 서로 기준이 다른 경매자료와 배당자료를 단순 비교하지 않음

이 자료는 이미 사고가 발생한 사례이므로 계약 전 사고확률이나 위험점수 계산에는 사용하지 않고, 위험근거를 설명하는 참고자료로만 사용했습니다.

결과: [`analysis/03_auction_recovery`](../../analysis/03_auction_recovery)

### 4단계. 임대차 상담사례 분석

비식별 상담자료 938건에서 반복되는 위험상황을 분석했습니다.

`value_counts`와 `groupby`를 사용해 주택유형·선순위권리·보증보험·분쟁유형별 분포를 계산했습니다. 상담문장 3개 컬럼을 합친 뒤 `str.contains`로 근저당·말소·공동담보·압류·경매·보증보험 등 15개 키워드의 포함 건수를 확인했습니다.

- 경매·공매 관련 상담
- 보증금 미반환 상담
- 전세사기 의심 상담
- 근저당·선순위 권리 관련 상담
- 반환보증 가입 여부가 불분명한 상담

상담자료에서 주택유형·선순위 권리·보증 상태를 모르는 경우가 많았습니다. 따라서 모르는 값을 위험사실로 확정하지 않고 `required_checks`에 넣어 사용자가 확인하도록 설계했습니다.

결과: [`analysis/04_consultation_context`](../../analysis/04_consultation_context)

### 5단계. 최종 위험 규칙 설계

숫자 점수보다 사용자가 바로 이해할 수 있는 위험단계와 근거를 제공하도록 설계했습니다.

2~4단계에서 확인한 통계와 상담맥락을 함께 검토해 위험규칙 후보를 만들었습니다. 정상계약 분모가 없는 합성 사고자료이므로 통계값을 사고확률로 변환하지 않고, 확인된 사실은 `confirmed_risks`, 모르는 정보는 `required_checks`로 나누는 규칙으로 구현했습니다.

#### 위험단계

| 조건 | 결과 |
|---|---|
| 높은 위험 2개 이상 | 계약 전 재검토 |
| 높은 위험 1개 또는 중간 위험 2개 이상 | 주의 |
| 위험이나 확인사항이 1개 이상 | 추가 확인 필요 |
| 확인된 위험과 확인사항이 없음 | 기본 확인 |

#### 확인하는 위험요소

- 선순위 근저당 존재
- 근저당 말소 약속만 있고 실제 말소되지 않은 상태
- 압류·가압류 존재
- 공동담보 존재
- 반환보증 가입 어려움
- 검증된 주택가액 대비 높은 보증금비율
- 실제 보증금과 다른 다운계약 요구

반환보증은 `가입 가능성 추정`, `공식 가입 가능`, `신청 중`, `가입 완료`, `가입 어려움`, `확인 필요`의 6가지 상태로 나눴습니다.

결과: [`analysis/05_risk_rules`](../../analysis/05_risk_rules)

### 6단계. 분석 코드와 모의 결과 제작

설계한 규칙을 실제 코드와 JSON 데이터로 구현했습니다.

위험 판정 코드는 Python 조건문과 표준화된 상태값으로 작성했습니다. 같은 입력에는 항상 같은 결과가 나오도록 결과 생성 스크립트를 만들고, Python `unittest`로 경계값·미확인 정보·반환보증 6단계·입지정보 분리 여부를 검사했습니다.

- 시연용 모의 매물 5건 제작
- 주택유형·참고가격·권리관계·반환보증 상태 표준화
- 공항·군사시설·철도계획 입지 참고정보 제작
- 위험단계, 위험근거, 확인사항 자동 생성
- 필수정보가 얼마나 확인됐는지 분석 신뢰도 계산
- 네 가지 위험단계가 모두 포함된 결과 예시 5건 제작
- 위험 규칙과 결과 검증 테스트 18개 작성

### 7단계. 백엔드 전달 자료 작성

백엔드 담당자가 분석 결과를 연결할 수 있도록 요청·응답 구조와 사용방법을 정리했습니다.

- 최소 요청값: `property_id`, `planned_deposit`
- 반환값: 매물정보, 보증상태, 위험단계, 위험근거, 확인사항, 분석 신뢰도, 입지정보
- 잘못된 입력에 대한 권장 오류 처리
- 실제 API 라우터는 수정하지 않고 데이터 분석 결과만 전달

## 작업하면서 정한 중요한 원칙

1. 사고확률과 100점 위험점수를 만들지 않습니다.
2. 확인되지 않은 정보는 안전하다고 처리하지 않습니다.
3. 모르는 값은 확정 위험이 아니라 추가 확인사항으로 안내합니다.
4. 분석 신뢰도는 안전도가 아니라 필수정보의 확인 정도입니다.
5. `기본 확인`은 계약이 안전하다는 의미가 아닙니다.
6. 입지정보는 근저당·압류·반환보증 같은 계약 위험을 낮추지 않습니다.
7. 합성데이터와 모의정보를 실제 공식자료처럼 표현하지 않습니다.
