# 안심계약 레이더

HUG 보증사고 데이터와 아이엔 임대차 상담데이터를 활용해, 임차인이 계약 전에 위험신호를 확인하고 조건 변경 효과를 비교할 수 있도록 돕는 계약 전 대응 시뮬레이터입니다.

## 핵심 아이디어

안심계약 레이더는 단순히 "위험합니다"라고 알려주는 서비스가 아니라, 어떤 조건 때문에 위험도가 올라갔는지 설명하고 어떤 조건을 바꾸면 더 안전해지는지 보여줍니다.

사용자는 지역, 주택유형, 보증금, 주택가액, 선순위권리, 보증보험 상태 등을 입력합니다. 서비스는 입력값을 HUG 사고 데이터와 아이엔 상담사례의 반복 위험신호와 비교해 4축 위험점수, 위험근거, 유사사례, 행동 체크리스트를 제공합니다.

## MVP

이번 해커톤에서 구현할 최소 기능은 다음과 같습니다.

1. 계약정보 입력
2. 4축 위험점수 분석
3. 위험근거 설명
4. 조건 변경 시뮬레이션
5. 행동 체크리스트

## 4축 위험점수

| 축 | 설명 | 최대 점수 |
|---|---|---:|
| 보증금 구조 | 보증금이 주택가액에 얼마나 가까운지, 주택유형별 사고 기준선과 비교 | 35 |
| 권리관계 | 근저당, 압류, 공동담보, 선순위 임차인 등 먼저 회수될 권리 확인 | 25 |
| 보호장치 공백 | 보증보험 가입 가능 여부, 말소 특약, 확인되지 않은 정보 여부 | 20 |
| 유사사례 심각도 | 비슷한 상담사례가 보증금 미반환, 경매, 전세사기 의심으로 이어졌는지 확인 | 20 |

주의: 위험점수는 전세사기 발생확률이 아니라, 제공 데이터에서 반복된 위험신호를 현재 계약조건과 비교한 상대적 의사결정 지원 지표입니다.

## 사용 데이터

| 데이터 | 활용 목적 |
|---|---|
| HUG 보증사고/대위변제 데이터 | 사고 규모, 보증금 구조, 주택유형별 위험 기준선 |
| 경매현황/배당내역 데이터 | 사고 이후 회수율과 회수 기간의 불확실성 설명 |
| 아이엔 비식별 상담데이터 | 실제 임차인이 겪는 분쟁 유형, 진행단계, 유사 상담사례 |

초기 분석에서 확인한 주요 포인트:

- 전세보증 대위변제 규모는 2023년과 2024년에 크게 집중됨
- 경매현황 기준 가중 회수율은 약 29.1%
- 배당금액이 0원인 건은 약 64.9%
- 주요 위험 주택유형은 다세대주택, 오피스텔, 아파트
- 상담 데이터 주요 분쟁은 경매·공매, 보증금미반환, 전세사기

## 팀 역할

| 역할 | 담당 범위 |
|---|---|

| 백엔드/API/통합 | 입력값 검증, 분석 API, 점수/사례/체크리스트 모듈 통합 |
| 프론트엔드/UX | 계약정보 입력 화면, 결과 리포트, 레이더 차트, 시뮬레이션 UI |
| 기획/발표/데모 | 문제정의, 사용자 시나리오, 발표자료, 데모 대본, Q&A 준비 |

## API 계약

### POST `/analyze`

계약정보를 받아 위험분석 결과를 반환합니다.

요청 예시:

```json
{
  "region": "부산광역시 강서구",
  "housing_type": "multi_unit",
  "house_value": 220000000,
  "deposit": 200000000,
  "mortgage_status": "exists",
  "seizure_status": "none",
  "joint_collateral": "unknown",
  "guarantee_status": "unknown",
  "down_contract": false
}
```

응답 예시:

```json
{
  "total_score": 72,
  "grade": "높음",
  "deposit_ratio": 90.9,
  "category_scores": {
    "deposit_structure": 27,
    "rights": 20,
    "guarantee": 12,
    "information": 13
  },
  "reasons": [
    "보증금이 주택가액의 90%를 초과합니다.",
    "근저당이 확인되어 권리관계 검토가 필요합니다.",
    "보증보험 가입 가능 여부가 확인되지 않았습니다."
  ],
  "similar_cases": [],
  "checklist": [
    "계약 전 보증보험 가입 가능 여부를 확인합니다.",
    "등기부등본 을구의 근저당 채권최고액을 확인합니다.",
    "잔금 전 근저당 말소 특약을 계약서에 명시합니다."
  ],
  "disclaimer": "상대적 위험신호 지표이며 법률 판단이나 사고확률이 아닙니다."
}
```

## 개발 우선순위

| 우선순위 | 기능 |
|---|---|
| Must | 입력 폼, 점수 계산, 위험요인 TOP 3, 레이더 차트, 조건 변경 전후 비교 |
| Should | 유사 상담사례 1~3개, 행동 체크리스트, 지역/주택유형 기준 설명 |
| Could | PDF 리포트 저장, 카카오 공유 문구, 상세 데이터 필터 |

## 발표 데모 시나리오

대표 사용자는 부산 오피스텔 전세계약을 앞둔 사회초년생입니다.

데모 입력값:

- 지역: 부산광역시 강서구
- 주택유형: 오피스텔 또는 다세대주택
- 보증금: 2억 원
- 주택가액: 2억 2천만 원
- 선순위권리: 근저당 있음
- 보증보험: 미확인
- 말소특약: 없음

서비스는 현재 계약의 위험요인을 설명한 뒤, 보증금 조정, 근저당 말소 특약, 보증보험 확인을 반영했을 때 점수가 어떻게 바뀌는지 비교합니다.

## 멘토링 질문

1. 계약 전 위험신호 분석과 조건 변경 시뮬레이션 방향이 발제 의도에 맞는지
2. 위험점수를 사고확률이 아니라 상대적 위험신호 지표로 표현하는 것이 적절한지
3. 머신러닝 모델이 꼭 필요한지, 규칙 기반 점수와 유사사례 검색으로 충분한지
4. 심사에서 데이터 분석 깊이와 서비스 완성도 중 무엇을 더 강조해야 하는지
5. 유사 상담사례는 조건 기반 매칭으로 충분한지
6. 법률/부동산 표현에서 조심해야 할 문구가 있는지
7. 조건 변경 시뮬레이션에서 어떤 변경 조건을 가장 강조해야 하는지
